# Stage 1 Frontend Requirements — TCM Intelligent Consultation Chat UI

## 1. Overview

Replace `frontend-minimal/` with a production-quality, Claude-style single-page chat application for the Traditional Chinese Medicine (TCM) consultation system. The new frontend must feel like a real AI assistant product, not a developer console.

## 2. User Roles

| Role | Core Need |
|---|---|
| 患者 / Patient | Ask about symptoms, medicines, dosage, contraindications in natural language |
| 中医药爱好者 / TCM Enthusiast | Explore theory, herbs, classical formulas |

Both roles share the same interface; no login or role-selection required.

## 3. Functional Requirements

### 3.1 Streaming Chat Output
- Every assistant response must stream token-by-token (SSE from `/api/v1/qa/stream`).
- The user sees text appearing progressively, not as a single blob.
- A **Stop** button appears while streaming and aborts the in-flight request.
- Markdown in responses must render correctly (bold, bullets, tables, code blocks).

### 3.2 Guided Follow-up Questions ("猜你想问")
- After each assistant response completes, display **3 follow-up suggestion chips** below the message.
- Chips are generated by the LLM at answer time and delivered via the `suggest` SSE event.
- Clicking a chip immediately sends that text as the next user message.
- On the **home / cold-start screen**, show **6–8 pre-set TCM topic chips** (static, from `lib/topics.ts`) so the user has an instant entry point without typing.

### 3.3 Session Management
- Left sidebar lists all past sessions (title = first 30 chars of first user message, or "New Chat").
- **New Chat** button starts a fresh session.
- Clicking a session loads its message history (fetched from backend on demand).
- Each session row has a **Delete** icon; confirmation before delete.
- Active session is visually highlighted.

### 3.4 Error Handling
- Network errors, timeout, or backend error codes surface in an `ErrorBanner` at the top of the chat area (dismissible).
- Error messages are human-readable, mapped from backend codes via `lib/errorMap.ts`.
- On streaming failure mid-response, the partial message is preserved and a small inline error notice is appended.

### 3.5 Accessibility & Non-functional
- Dark theme by default; respects `prefers-color-scheme` if possible.
- Mobile-responsive layout (hamburger sidebar on small screens).
- First contentful paint < 2 s on local dev server.
- No user authentication required.
- No persistent storage in the browser beyond the active session ID (backend handles history).

## 4. Out of Scope (this stage)
- Admin panel, analytics, user accounts
- i18n beyond Simplified Chinese
- Offline / PWA
- Custom voice input
